# Écarts Windows NOMMÉS — lisible par ci/verdict-windows.ps1.
#
# Format : <motif d'identifiant de test>|<raison, une ligne>
# Le motif est comparé au DÉBUT de l'identifiant (FAILED tests/x.py::test_y).
# Un échec qui ne correspond à aucune ligne fait échouer le job : c'est la
# garantie qu'un écart ajouté ici est un écart assumé, jamais un oubli.
#
# Règle d'or : une ligne ajoutée doit porter la raison EXACTE pour laquelle le
# test ne peut pas passer sur Windows, et la contrepartie (ce qui prouve la
# même chose ailleurs). Une ligne sans contrepartie est une preuve perdue.
#
# Comment les lignes ci-dessous ont été établies, pour qu'on puisse les
# revérifier : chaque test a été exécuté sur le banc POSIX avec les primitives
# déclarées ABSENTES (simulation de ce qu'est Windows pour ce produit — voir
# tests/test_ecarts_windows.py). Ceux qui échouent alors avec l'OSError nommé
# de seamtech_search/plateforme.py sont ceux qu'aucune adaptation de banc ne
# peut faire passer sur Windows : c'est le confinement du produit qui manque,
# pas un service. Les autres ne sont PAS nommés ici — ils instruisent.

# --- Limite de SYSTÈME : confinement des fichiers par descripteur ----------
# Le produit épingle un dossier par descripteur (os.open(dir_fd=…),
# O_NOFOLLOW) et l'inventorie sans jamais traverser de lien. Windows n'a ni
# dir_fd ni O_NOFOLLOW : il n'existe pas d'équivalent, et un remplacement
# « à peu près » serait un confinement de façade. La contrepartie est double :
#   * le refus est NOMMÉ (seamtech_search/plateforme.py), pas une panne ;
#   * le déploiement Windows se fait dans Docker avec des conteneurs LINUX
#     (décision de déploiement, pas un pis-aller de CI) ;
#   * la suite POSIX complète tourne sur Linux à chaque commit et couvre ces
#     mêmes tests.

# Au run 41420706781, 71 échecs : 19 sont expliqués ci-dessus, les autres NON.

# soit corrigées (défaut produit), soit nommées ici avec leur raison.

# --- Écarts par CAUSE -----------------------------------------------------
# Forme : CAUSE|<message exactement prononcé par le produit>|<raison>
#
# Pourquoi : au run 41433225057, la suite sans service compte 314 échecs pour
# UNE SEULE cause — « Lecture confinée du bundle indisponible sur cette
# plateforme ». Les énumérer un par un n'apprendrait rien et vieillirait mal ;
# un écart par cause accepte tout échec dont le message est CELUI-LÀ. La
# contrepartie est la même que pour les motifs par test : refus nommé par
# seamtech_search/plateforme.py, déploiement Windows dans des conteneurs Linux,
# et couverture intégrale de ces tests par la CI Linux à chaque commit.
#
# Ce qui n'entre PAS dans un écart par cause : un message vague. Si le produit
# disait « erreur », l'écart engloutirait tout. Les trois messages ci-dessous
# nomment chacun une capacité absente, ce qui les rend opposables.
CAUSE|Lecture confinée du bundle indisponible sur cette plateforme|lecture confinée du bundle (procfs_fd + descripteur ancré) : primitive POSIX inexistante sur Windows ; refus nommé par plateforme.py ; couvert par CI Linux ; déploiement Windows = Docker Linux
CAUSE|Capacité de plateforme absente : scan_ancre_descripteur|scan d'un dossier ancré par descripteur (dir_fd + O_NOFOLLOW) : sans lui, l'import refuse au lieu de traverser des liens ; idem
CAUSE|Capacité de plateforme absente : procfs_fd|résolution d'un chemin par /proc/self/fd : équivalent de confinement POSIX absent de Windows ; idem
CAUSE|Capacité de plateforme absente : verrou_flock|verrou coopératif flock : Windows verrouille par plage d'octets, pas par descripteur de répertoire ; idem
